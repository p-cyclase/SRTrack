# 3. 時間変換と編集同期

## 3.1 初期版の変換モデル

固定の正の速度、ループなしの場合、シーン時刻 `T` と SRT 元時刻 `s` の関係は次のとおりとする。SRTrack Object の `再生位置` は秒、`再生速度` は百分率であり、標準動画オブジェクトと同じ単位を使う。倍率 `v` は `再生速度 ÷ 100` である。

```text
t = T - A
s = P + v × t
T = A + (s - P) / v
```

`A` はオブジェクト開始時刻、`P` は再生開始位置、`v` は再生速度である。`v = 1` は等速、`v = 2` は 2 倍速、`v = 0.5` は半速を表す。再生範囲終端 `E` は SRT 元時刻で表し、Object が参照できる範囲を半開区間 `[P, E)` と定義する。動画全長 `D` は Importer が取込時に動画オブジェクトと同一のフレーム境界値で設定し、`P`〜`E` の通常の時間変換には使わない。

エクスポート時は、各 SRT 区間をオブジェクトが実際に参照する SRT 範囲と交差させる。交差した両端を `T` に変換し、オブジェクトのシーン上の範囲で切り詰める。交差が空なら出力しない。

## 3.2 フレームと丸め

プロジェクトのフレームレートは有理数 `rate / scale` として扱う。フレーム `n` の時刻は `n × scale / rate` 秒であり、SRT の `m` ミリ秒に対応する理論上のフレーム位置は `m × rate / (1000 × scale)` である。

途中でフレームへ繰り返し丸めず、可能な限り整数ミリ秒または有理数で計算して最後に丸める。29.97 fps 系を含む分数フレームレートで、丸め方向と許容誤差を検証する。

## 3.3 編集への追従

SRTrack Object は、対応する動画オブジェクトと同じ時間的な編集結果を持つことを目標とする。動画と SRTrack Object をグループ化し、移動、分割、伸縮、再生開始位置の変更、速度変更を同期させる。これにより、動画の編集後の範囲へ元 SRT を正しく対応づける。

初期版で各操作をどこまで同一にできるかは SDK と実機で検証する。特に分割、端の変更、再生開始位置、速度変更を対象 AviUtl2 版の標準動画と比較し、同期できない操作は対応外として明示する。

### 3.3.1 分割・伸縮の保留

標準動画オブジェクトは、再生位置が「移動無し」または「再生範囲」で、かつループ再生しない場合、開始・終了位置の変更や分割に合わせて再生位置を調整する。この挙動を SRTrack Object が同一に再現するには、開始位置 `P` に加えて、動画の再生範囲の終端位置 `E` を定義・同期する必要がある。

SRT には動画長が記録されないため、終端を SRT の最終字幕時刻などから補ってはならない。SRTrack Importer が動画オブジェクトと同じフレーム境界の終端で `E` を初期化する。取込後は、グループ内の標準動画に本体が適用した `P`・`E`・再生速度の更新結果を Object へ反映する方式を検討する。標準動画と同じ規則を Object 側で再実装する方針は採らない。ただし、この常駐同期をどのコンポーネントの責務とするか、名称・配布単位も含めて再定義するまで実装は保留とする。

## 3.4 初期版の対象外

速度 0、逆再生、ループ、可変速度、中間点、時間制御、シーンをまたぐ利用は初期版では対象外である。分割・伸縮への自動追従も保留とする。再生範囲終端 `E` を Importer が初期化する設計は決定済みだが、標準動画の更新結果を Object へ継続反映するコンポーネントの設計・実装・実機検証は未完である。特に SRT の最終字幕時刻は元動画の長さを示さないため、SRT 単体でループ範囲や分割・伸縮後の終端を決めてはならない。

将来のループでは、Importer が取得した不変の動画全長 `D` を元動画時間の周期として用いる。`D` は移動・分割・伸縮により変化してはならず、現在の利用範囲を示す `P`・`E` と混同しない。対応を追加する場合、上記の線形変換式をそのまま適用してはならない。
