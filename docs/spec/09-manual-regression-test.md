# 9. Preview／Exporter 手動回帰テスト

## 9.1 目的と範囲

Git 管理するテスト用 AviUtl2 プロジェクトを用意し、SRTrack の Preview と Exporter に対する代表的な手動回帰確認を、同じ素材・同じ配置で繰り返せるようにする。

このプロジェクトは Importer のテストを目的としない。Importer は空シーンへ動画または SRT をドロップする操作自体が確認対象であるため、別の手動チェックとして扱う。

PSDToolKit のセリフ準備は外部プラグインに依存する。基本プロジェクトの必須条件には含めず、導入環境で実施する任意確認とする。

## 9.2 配置と管理方針

管理位置は次のとおりとする。

```text
tests/
  manual/
    SRTrack-Regression.aup2
    README.md
    checklist.md
    fixtures/
      regression-video.mp4  # ローカル配置・Git 管理外
      regression-video.srt  # Git 管理
      fix.srt               # Git 管理
```

- 素材は短い自作動画と、権利関係が明確なテスト字幕だけを使う。基準動画にはSRTの各区間と対応する表示を含め、Previewを目視比較できるようにする。
- `.aup2` と SRT fixture は Git 管理する。動画 fixture は容量・作成日時などの環境差を持つため Git 管理せず、各開発環境へ同じ名前でローカル配置する。Exporter が生成する SRT と PSDToolKit の生成物も Git 管理しない。
- AviUtl2 が保存する `.aup2` の参照先は現時点では絶対パスである。配布・別環境で開く場合は、`fixtures/` 内の同名ファイルを指定し直す手順を `README.md` に案内する。
- 実動画や個人制作物、外部プラグインの配布物は同梱しない。
- テストプロジェクトは、初期設定を変更しない状態で開く。確認ごとの設定変更は `checklist.md` に明記する。

## 9.3 基準設定

Exporter の基準は初期設定とする。

| 項目 | 基準値 |
| --- | --- |
| 最小表示時間 | `1.000` 秒 |
| 出力対象時間範囲 | シーン全体 |
| 対象レイヤー | すべてのレイヤー |
| 対象 Object | テキスト、SRTrack Object |
| ルビ・絵文字のカッコ書き | オン |
| 待機・クリアを反映 | オン |
| 同時開始時の並び順 | 上のレイヤーから |

短い字幕や `<c0.5>` の確認も、基準設定では1秒未満の候補が結合・延長されることを期待結果とする。字幕境界そのものを確認する限定ケースだけ、最小表示時間を `0.500` 秒へ変更する。その変更は確認後に基準値へ戻す。

## 9.4 プロジェクト内の必須ケース

### Preview

1. SRTrack Object を動画の1つ下のレイヤーへ置き、読み込んだ SRT の字幕が編集画面に表示される。
2. 動画と Object のタイムライン開始位置をずらして置き、動画の対応位置の字幕が表示される。
3. 動画の再生開始位置と再生速度を変更し、Preview が追従する。
4. Object の範囲中で上側に動画がない区間では、Preview が専用診断を表示する。動画とObjectの間にある非動画Objectは読み飛ばして、上側の直前動画Objectを参照する。
5. SRTrack Object (fix) は、自身の再生位置・速度に従って字幕を表示する。
6. SRTrack Object (txt) は、入力テキストを Object の座標で表示し、動画書き出しには描画しない。
7. `字幕プレビュー` のオン・オフが編集画面だけに反映され、動画出力には描画されない。
8. `SRTrack 設定` の全体 Preview をオフにすると、個別の `字幕プレビュー` がオンの Object も編集画面へ描画しない。再びオンにすると、個別設定を保持したまま表示を再開する。

### Exporter

1. 標準テキスト、SRTrack Object、SRTrack Object (fix)、SRTrack Object (txt) を同一プロジェクトから出力する。
2. 各字幕候補は、別候補の開始・Object 終端・SRTrack Object の参照動画不在で終了する。
3. 同時開始の複数テキストを置き、上のレイヤーからの本文順と、短い字幕の結合を確認する。
4. `<r>`、`<w>`、`<c>`、倍率付き待機・クリア、ルビ、絵文字、コメント、Lua スクリプトを含むテキストを出力する。
5. 基準設定の最小表示時間 `1.000` 秒で、短い候補が想定どおり結合・延長されることを確認する。
6. 限定ケースとして最小表示時間を `0.500` 秒へ変更し、`<r10>AB<c0.5>CD` などのクリア境界がSRT候補として出力されることを確認する。
7. フレーム範囲選択出力で、範囲端をまたぐ字幕の切り出しと、選択開始を `00:00:00,000` とする再基準化を確認する。
8. `上のレイヤーから` と `下のレイヤーから` を切り替え、同時開始字幕の本文順だけが変わることを確認する。

## 9.5 記録方法

`checklist.md` では各ケースについて、操作、期待する Preview または SRT の結果、確認日、AviUtl2・SRTrack の版、結果を記録する。確認済みは「概略確認」であり、全フレーム・全環境を網羅した保証とは扱わない。

固定の正解 SRT は管理しない。SRTrack は開発中であり、実装・仕様を変更するたびに固定期待値を更新すると、期待値自身の誤りや古い仕様への追従を見落とすためである。出力された SRT とテストマップを照合し、各ケースで何が起きたかを観察・検討する。

## 9.6 現在の手動回帰プロジェクト

`SRTrack-Regression.aup2` は以下の構成を実装済みである。SRTrack を更新するたびに「プロジェクトを開く → 標準設定で Exporter を実行 → 出力 SRT を確認する」ことで、基礎挙動を一巡できる実験場として使う。

### 素材の再利用

`fixtures/regression-video.mp4`（30秒・30fps）と `fixtures/regression-video.srt` は作り直さない。同じ動画ファイルを複数の動画 Object から参照し、再生開始位置・再生速度・タイムライン位置だけを変える。動画に含まれる3秒ごとの基準表示と、同名 SRT の `映像基準 A`〜`J` は、各動画追従ケースの目視確認にも使う。

`fix.srt` は `fix` 型専用の識別本文を持つ小さな fixture である。動画素材を追加する必要はない。

### タイムライン配置

プロジェクト全長は222秒である。各動画追従 Object の上側には、参照対象となる最も近い動画 Object を置く。210〜216秒には、動画と SRTrack Object の間へ空の非動画テキスト Object を置き、非動画 Object を読み飛ばして最も近い上側動画 Object が選ばれることを確認する。216〜222秒には `txt` 型を置き、動画を参照しない補足字幕を確認する。

| 区間 | 動画／Object の設定 | 配置する本文 | 主な観察点 |
| --- | --- | --- | --- |
| 0〜30秒 | 動画 `P=0`、速度100%、動画追従Object | `映像基準 A`〜`J` | 基本 Preview、基本 SRT読込、通常速度 |
| 30〜45秒 | 同じ動画 `P=0`、速度200%、動画追従Object | 圧縮された `映像基準 A`〜`J` | 動画速度と字幕時刻の追従 |
| 45〜60秒 | 同じ動画 `P=10`、速度100%、動画追従Object | `映像基準 D`以降 | 動画の再生開始位置 |
| 60〜75秒 | 動画 `P=0`、速度100%、Objectは63秒から開始 | `映像基準 B`以降 | 動画とObjectのタイムライン開始位置差 |
| 75〜90秒 | 動画を置かず、動画追従Objectだけを置く | SRTは指定したまま | Previewの専用診断、Exporterでは該当区間を字幕なしとして継続 |
| 90〜105秒 | SRTrack Object (fix)、`P=0`、速度100% | `FIX-A`等 | fix型の基本出力・Preview |
| 105〜110秒 | 標準テキストを4レイヤー同時開始 | `SIM-A`〜`SIM-D` | 同時開始、上／下レイヤー順、短い字幕の結合 |
| 110〜116秒 | 標準テキスト | `<r10>AB<c0.5>CD` | `<r>`、`<c>`、初期値1秒での結合。必要時は最小表示時間0.500秒で境界を観察 |
| 116〜122秒 | 標準テキスト | `<r10>A<w1>B<w*0.2>CD` | `<r>`、`<w>`、`<w*>`、文字送りを個別SRTにしない処理 |
| 122〜128秒 | 標準テキスト | `<r10>AB<c*0.2>\nCD` | `<c*>`、`<c>`直後の改行無視、クリア後の次字幕 |
| 128〜134秒 | 標準テキスト | ルビ、絵文字、装飾、コメント、Lua | 各変換チェック、常時削除する構文 |
| 134〜140秒 | 動画追従Objectの範囲へ標準テキストを重ねる | `INTERRUPT` | 他字幕開始によるSRT候補の中断と、次の元SRT字幕の開始 |
| 140〜150秒 | Object終端を動画より早くする | `映像基準` の途中でObject終了 | Object終端による字幕終了 |
| 150〜180秒 | 1つのObject内で、動画 `P=0` の10秒間、動画なしの10秒間、動画 `P=20` の10秒間 | 前半は `映像基準 A`〜`D`、後半は `映像基準 G`〜`J` | 動画終了後の字幕停止と、動画再出現後の再開 |
| 180〜210秒 | 1つのObject内で、動画 `P=0`・速度100%の15秒間と、動画 `P=0`・速度200%の15秒間を連続配置 | 前半は `映像基準 A`〜`E`、後半は圧縮された `映像基準 A`〜`J` | 動画切替時に再生位置・速度を読み直す時間変換 |
| 210〜216秒 | 動画と動画追従Objectの間に、空の標準テキストObjectを配置 | `映像基準 A`〜`B` | 非動画Objectを読み飛ばし、上側の直前動画Objectを参照 |
| 216〜222秒 | SRTrack Object (txt) | `TXT-NOTE: SRT にのみ出力する補足字幕` | txt型のPreview・一候補出力・動画非描画 |

### 出力と観察の方法

初回は Exporter の基準設定（最小表示時間1.000秒、全レイヤー、全時間範囲、上のレイヤーから）でシーン全体を出力する。出力 SRT の本文にある `映像基準`、`FIX`、`TXT-NOTE`、`SIM`、`AB`／`CD`、`INTERRUPT` などを手掛かりに、対応する区間をテストマップから確認する。

必要な場合だけ、次の焦点化した追加出力を行う。

- 最小表示時間を `0.500` 秒へ変更し、110〜128秒の時間制御境界を観察する。
- 同時開始時の並び順を「下のレイヤーから」へ変更し、105〜110秒の本文順だけが反転するかを見る。
- フレーム範囲選択を設定して、SRT候補の範囲端での切出しと時刻のゼロ基準化を確認する。

これらの設定変更は恒久設定として残さず、確認後に基準値へ戻す。

## 9.7 今後の育成方針

手動回帰プロジェクトは完成した固定テストではなく、SRTrack の新機能・バグ修正に合わせて育てる共通の実験場とする。ただし、通常の基準出力を毎回エラー付きにしないため、確認項目を次の二層に分ける。

### 静的ベースライン

プロジェクトを開き、Exporter を基準設定のまま実行するだけで確認できる配置済みケースである。新しい実装が既存機能を壊していないかを素早く観察する目的で、意図的な読込失敗や無効設定は常設しない。仕様どおりの情報ログである `EXP-VIDEO-END` は許容するが、警告・エラーのない出力を基準とする。

同じ `regression-video.mp4` を複数回配置した次の二つは、静的ベースラインへ追加済みである。

| 追加区間 | 配置 | 観察点 |
| --- | --- | --- |
| 150〜180秒 | 1つの `SRTrack Object` の直上に、動画A、動画なしの区間、動画Bを順に置く | 同一Object内での動画終了、字幕停止、動画再出現後の再開 |
| 180〜210秒 | 1つの `SRTrack Object` の直上に、再生開始位置または速度が異なる複数動画を連続配置する | 動画切替ごとに開始位置 `A`、再生位置 `P`、速度を読み直す時間変換 |

追加時に更新するプロジェクト全長、テストマップ、`README.md`、`checklist.md` は今回同期済みである。動画fixtureの新規作成は不要とし、既存の30秒・30fps素材と対応SRTを再利用した。

### 焦点テスト

操作、利用者設定、または意図的な異常入力を必要とする確認は、基準プロジェクトの指定Objectを一時変更して行い、確認後に元へ戻す。操作と期待結果は `checklist.md` に記録する。

- 動画またはObjectの分割・伸縮後の追従
- フレーム範囲選択、オフセット、最小表示時間、同時開始順の設定
- 存在しないSRT、SRT内の不正区間、無効な動画全長・再生設定などの診断
- Exporterの警告・エラーのモーダルと共通診断ログの一致

Importerのドロップはファイルドロップ操作そのものが検証対象であるため、このプロジェクトへ組み込まない。空シーンで動画ペア取込、SRT単体取込、通常入力への委譲を別途確認する。

## 9.8 常設診断との連携

手動回帰プロジェクトは、Preview／Exporter の常設診断を確認するための再現環境でもある。診断実装後は、少なくとも次を確認する。

1. 75〜90秒の動画追従 Object について、Preview が動画不在の理由を表示し、Exporter は `EXP-VIDEO-END` の情報ログだけを残して警告モーダルを表示しない。
2. Exporter が読み取れない入力や除外した区間を検出した場合、通常の出力継続を妨げず、詳細レポートから対象と失敗段階を確認できる。
3. Exporter のモーダル表示内容と共通診断ログの記録内容が一致し、診断情報をコピーできる。
4. Importer の異常時はモーダルを表示せず、通常入力への委譲結果を共通診断ログから確認できる。
5. 正常な基準プロジェクトでは、不要な警告や個人情報を含む診断が出ない。

常設診断の詳細な表示形式とエラーコードは [05-errors-and-validation.md](05-errors-and-validation.md) に従う。テストプロジェクトを Issue 添付用の素材として配布する場合も、ローカル動画 fixture や生成済み出力を不用意に添付せず、利用者が内容を確認してから共有する。
