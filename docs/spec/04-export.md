# 4. 字幕ソースの統合と SRT 出力

> **実装状態**：Exporter は初期版完成とする。三種の SRTrack Object を含む字幕候補の統合、短字幕結合、フレーム範囲選択、時間制御文字、動画不在後の再出現を含む出力を実装・概略確認済みである。複雑な編集条件との完全一致、対応環境での網羅試験、表示上の細部は今後のバグフィクス・互換性確認で扱う。

## 4.1 字幕ソース

SRTrack Exporter は次の情報を共通形式へ正規化して後段へ渡す。

| 項目 | 内容 |
| --- | --- |
| 開始・終了 | シーン時刻上の字幕区間 |
| 本文 | 改行を保持した字幕文字列 |
| 出所 | 標準テキスト、対応する外部字幕準備オブジェクト、SRTrack Object、SRTrack Object (fix)、SRTrack Object (txt) |
| レイヤー | 安定した並び順と利用者による選択に使用 |
| 元順序 | 同時刻・同一ソース時の安定した順序に使用 |

標準テキスト、対応する外部字幕準備 Object、三種の SRTrack Object は、いずれも並列の字幕ソースである。一方を他方より本質的に優先するカテゴリにはしない。`SRTrack Object` は Object 範囲内で上側の直前動画Objectごとの有効区間を読み、開始位置差を含む時間変換を行う。`SRTrack Object (fix)` と `SRTrack Object (txt)` も `SRTrack Object` と同じ対象設定で字幕ソースに含める。

各 Object 単独の SRT 時刻は Preview と Exporter で一致させる。テキスト等との統合・結合・オフセット後の最終 SRT は Preview の対象外である。

## 4.2 字幕候補の統合

### 4.2.1 候補の生成

Exporter は、選択された各字幕ソースから字幕候補を生成する。

- 標準テキストと外部字幕準備 Object は、Object の開始を候補の開始、Object の終了を候補の終了とする。
- `SRTrack Object` と `SRTrack Object (fix)` は、SRT の各字幕をそれぞれ独立した候補とする。時間変換、有効区間、上側の直前動画Objectがない区間は [時間変換と動画参照](03-timing.md) に従う。
- `SRTrack Object (txt)` は、空でない入力テキストを Object の開始から終了までの一つの候補とする。
- `SRTrack Object` では、上側に動画がない区間を候補に含めない。参照動画がなくなった時点で候補は終了し、後に再出現した場合は別の候補として開始する。

> **実装予定：中間点区間をまたぐ SRT 字幕**
>
> [時間変換と動画参照](03-timing.md) の中間点対応では、内部の時間変換だけを動画 Object の区間ごとに分ける。SRT 字幕自体を中間点で機械的に前後へ分割して再結合する方式は採らない。各区間では、その区間の SRT 元時刻範囲内で**開始する**字幕だけを新しい候補として生成する。前の区間で開始した字幕は前区間の速度による終了時刻を保持し、次区間で重複して候補を生成しない。
>
> 後続区間で開始する候補が前の候補の終了時刻に重なる場合は、通常の開始・終了イベント規則に従って後続候補の開始時刻で前の候補を終了する。これにより、中間点をまたぐ同一字幕が二重の同文字幕として出力されることを避ける。中間点をまたぐ長い字幕の終了時刻は、その字幕が開始した区間の速度による近似値となる。

この段階で、候補の本文、開始・終了、レイヤー番号、同じレイヤー内での安定した元順序を保持する。SRT、テキスト、外部字幕準備を別々の優先カテゴリとしては扱わない。

### 4.2.2 開始・終了イベント

すべての候補を開始時刻順に処理する。候補が開始すると、直前に表示中の候補はその開始時刻で終了する。候補自身の終了時刻、Object の終了、または `SRTrack Object` における上側の直前動画Objectの消失も、表示中の候補を終了する境界である。

中断された候補は再開しない。同じ SRT 内の後続字幕を含む別の候補は、本来の開始時刻で新たに開始する。

同一フレームに複数の候補が開始する場合は、Layer 1 側（レイヤー番号が小さい側）から順に開始イベントを処理する。同時開始順は**勝者を選ぶ優先順位ではない**。先に開始した候補が同時刻に終了することを許容し、すべての候補を内部結果に残す。同じレイヤー内では元順序で安定的に処理する。

たとえば同じフレームに Layer 1 から順に `a`、`b`、`c`、`d` が開始し、`d` が 1 秒間表示される場合、内部結果は順に 0 秒の `a`、0 秒の `b`、0 秒の `c`、1 秒の `d` となる。これらは後段の短字幕処理で 1 秒の `abcd` になる。

SRT 内で字幕時刻が重複することは正常入力として想定しない。検出した場合も同じ開始・終了規則を適用し、後から開始する候補が表示中の候補を終了する。

### 4.2.3 短い字幕の結合と延長

開始・終了イベントを処理した直後は、表示時間が 0 秒の候補も削除しない。「最小字幕時間」は `0.000` 秒以上で指定し、初期値は 1.000 秒とする。この値は、短い字幕を次の字幕へ結合する探索距離ではなく、各字幕でまず確保を試みる表示時間である。ゼロ秒字幕専用の例外処理は設けない。

候補を開始時刻順に処理し、候補の開始時刻に最小字幕時間を加えた時刻を「必要終了時刻」とする。候補がすでに必要終了時刻まで続く場合は、そのまま出力する。短い候補は、直後の候補との開始時刻を次のように判定する。

1. 直後の候補がない場合、または直後の候補の開始時刻が必要終了時刻以降の場合は、現在の候補を必要終了時刻まで延長する。直後の候補が必要終了時刻ちょうどに始まる場合も、結合せず別字幕とする。
2. 直後の候補の開始時刻が必要終了時刻より前の場合は、現在の候補を延長すると重複するため、現在の本文を直後の候補の本文の前へ結合する。区切り文字は追加せず、各候補内に元からある改行は保持する。結合後の候補は、先行候補の開始時刻と後続候補の終了時刻を引き継ぎ、その結合後の長さで改めて同じ判定を行う。

したがって、短い候補が複数連続する場合は、結合後の候補が最小字幕時間を満たすまで後続候補との判定を繰り返す。一方、次の候補が必要終了時刻より後にある場合は、時間的な間隔が短くても本文を結合しない。

延長後の字幕は、動画、シーン、フレーム範囲選択の終端を超えていても切り詰めず、そのまま SRT に出力する。動画時間を超える SRT を外部サービスがどう扱うかは実機観察後に別途判断する。結合と延長を終えた後も正の表示時間を得られない候補だけを出力から除外する。

### 4.2.4 短い空白の補完

「最小字幕時間」は、従来の最小表示時間と同じ結合・延長規則を使う。入力可能な下限は `0.000` 秒とする。`0.000` を指定した場合、正の長さを持つ字幕には最小字幕時間による結合・延長を行わず、時間制御などの条件を個別に確認できる。

これとは別に、次の設定を `字幕の整形` へ追加する。

| 設定 | 初期値 | 意味 |
| --- | --- | --- |
| `短い空白を埋める` | オフ | 有効時、隣り合う字幕の間の短い空白を直前の字幕の延長で埋める |
| `最小空白時間` | 1.000秒（`0.000`秒以上） | 空白がこの値より短い場合に補完する判定値 |

補完は、4.2.3 の短字幕結合・延長と同時開始字幕の統合を終えた後、時間順に隣接する字幕を対象として行う。直前の字幕の終了から次の字幕の開始までが `最小空白時間` **未満**なら、本文は結合せず、直前の字幕だけを次の字幕の開始時刻まで延長する。ちょうど同値の空白は補完しない。

動画が不在になる区間、動画追従 Object の終端、別の Object への切替、またはフレーム範囲選択の境界をまたぐ空白は補完しない。したがって、この設定は連続した出力区間に生じる短い隙間だけを対象とし、動画不在などの意味を持つ無字幕区間を隠さない。初期値をオフとすることで、既存プロジェクトの出力は設定を有効にするまで変化しない。

本文の結合区切りを選べる設定は将来の改善項目とする。

### 4.2.5 出力時刻範囲と最終化

出力範囲はシーン全体または AviUtl2 のフレーム範囲選択とする。フレーム範囲選択では、範囲外の候補を除外し、範囲端をまたぐ候補は範囲内へ切り詰める。範囲開始時刻を `00:00:00,000` として全候補を再基準化する。

候補の統合、範囲による切り詰め、短い字幕の結合・延長、全体オフセットを順に適用して SRT を作る。番号は最終的な出力順に 1 から振り直す。

## 4.4 出力ファイル

- 形式：SubRip（`.srt`）
- 文字コード：UTF-8
- 時刻表記：`HH:MM:SS,mmm`
- 見た目：フォント、色、座標、縁取りは出力しない

標準テキストとセリフ準備から取得した本文では、制御文字、ルビ、絵文字、スクリプト文字列を [4.7 テキスト制御文字](#47-テキスト制御文字) に従って変換する。元の文章を黙って校正・翻訳しない。SRT ファイル本文はこの変換対象にせず、そのまま扱う。

## 4.5 保存先と動画書き出し範囲への配慮

SRTrack Exporter は、あくまで SRT を保存する通常のエクスポーターである。動画ファイルの書き出し、動画出力プラグインの操作、動画出力の成功・失敗・キャンセルとの連動は行わない。

SRT の保存時は通常の保存ダイアログを表示する。同名保存を強制せず、既存ファイルの上書き確認も OS の保存ダイアログに委ねる。

現行の Plugin SDK には、動画の書き出し先を直接取得する API はない。一方、保存済みの AviUtl2 プロジェクト（`.aup2`）はシーンごとに標準の `output.file` を記録する。Exporter は、SDK で取得した保存済みプロジェクトのパスを**読み取り専用**で開き、現在の `scene_id` に対応する `[scene.<scene_id>]` 節の `output.file` を取得してよい。

取得できた場合は、そのパスの拡張子を `.srt` に置き換えた値を通常の保存ダイアログの初期値として提案する。たとえば `output.file=C:\movie\sample.mp4` なら `C:\movie\sample.srt` を提案する。この値は候補にすぎず、保存先・ファイル名の強制、動画出力との連動、プロジェクトファイルの書き換えは行わない。

未保存プロジェクト、`output.file` 未設定、読取失敗、対応するシーン節がない場合は、既存の初期値または利用者が指定した保存先を使う。ディスク上の `.aup2` を読むため、保存後に書き出し先を変更してプロジェクトを未保存のままにしている場合は、最後に保存された値を候補にする。出力プラグイン固有の保存データや外部プラグインのファイルは調査しない。

出力範囲は、現行のシーン全体に加え、AviUtl2 のフレーム範囲選択を選べるようにする。手動の開始・終了フレーム指定は低優先度の将来項目とする。

フレーム範囲選択で出力する場合、範囲外の字幕は出力しない。範囲端にまたがる字幕は範囲内に切り詰め、範囲開始時刻を `00:00:00,000` とするよう全字幕時刻を再基準化する。番号は出力順に振り直す。統合、範囲による切り詰め、短字幕の結合・延長、オフセットの適用順は [4.2.4](#424-出力時刻範囲と最終化) に従う。

## 4.6 Exporter の UI 方針

Exporter は中級者以上が SRT 出力条件を指定する画面として、過度な装飾よりも対象範囲と処理結果を明確にする。対象を指定する操作は「出力対象」にまとめ、粒度が粗い順に次の三軸を並べる。

1. **対象時間範囲**：`シーン全体` または `フレーム範囲選択`。後者を選んだ場合は、その先頭を `00:00:00,000` として出力する。補足は主ラベルへ括弧書きで加えない。
2. **対象レイヤー**：`すべてのレイヤー` または `レイヤーを指定する`。指定時はレイヤー番号と完全一致のレイヤー名を使える。番号と名前の指定は合わせて適用し、両方に一致するレイヤーも一回だけ出力することを案内する。
3. **対象オブジェクト**：`テキスト`、`SRTrack Object`、`セリフ準備（PSDToolkit）` を個別に選ぶ。SRTrack Object の選択は三種すべてを対象にする。

時間範囲、レイヤー、Object の順に対象を絞り込むことで、利用者がどの字幕を出力するかを段階的に理解できるようにする。

字幕時間の処理のうち、各字幕の長さを扱う `最小字幕時間` は「字幕の整形」に置く。値は `0.000` 秒以上、既定 1.000 秒であり、短い字幕は次の字幕が最小字幕時間より前に始まる場合だけ結合し、それ以外は同じ値まで延長することを常時案内する。`短い空白を埋める` と `最小空白時間`（`0.000` 秒以上）も同じカードに置く。`出力時刻のオフセット` は完成した SRT 全体を前後へ移動する設定であるため、「出力対象」タブの最後に置く。秒数入力は小数点以下3桁のゼロ埋め表示（例：`0.000`、`1.000`）へ統一する。

画面右下には `エクスポート…` のボタンだけを置く。クリック後に通常の保存ダイアログを開く。Exporter の × または Esc、保存ダイアログのキャンセルで中止できるため、Exporter 画面内に重複するキャンセルボタンは置かない。

同時開始字幕の順序設定は、候補を捨てる優先順位ではない。本文の結合順を決める設定として `同時開始時の並び順` と表記し、`上のレイヤーから` と `下のレイヤーから` の二択を置く。初期値は前者とする。説明文には「同時に始まる字幕を結合する際の本文順」であることを記載する。

テキスト制御文字の変換設定は、仕様を定めたうえで「字幕の整形」に置く。装飾用制御文字・コメント・Lua スクリプトを削除する基本処理は設定にせず、ルビ・絵文字・`待機・クリアを反映` の3つをチェックボックスとして提供する。すべての初期値はオンとする。

### タブ構成

設定項目の増加で画面が縦に伸び続けないよう、Exporter は Windows 標準のタブコントロールで次の二画面へ分ける。

| タブ | 内容 |
| --- | --- |
| `出力対象` | 対象時間範囲、対象レイヤー、対象オブジェクト、出力時刻のオフセット |
| `字幕の整形` | 最小字幕時間、短い空白を埋める、最小空白時間、同時開始時の並び順、テキストの処理 |

`出力対象` は時間範囲だけでなくレイヤーと Object も指定するため、タブ名を「範囲指定」ではなく「出力対象」とする。このタブでは、対象時間範囲、対象レイヤー、対象オブジェクト、出力時刻のオフセットの順に並べる。`エクスポート…` はタブの外に固定表示し、タブを切り替えても入力済みの値は保持する。この操作では、両タブの設定をまとめて検証してから保存ダイアログを開く。

## 4.7 テキスト制御文字

AviUtl2 の公開テキスト仕様にある制御文字を対象に、SRT で表現できない見た目や実行結果をそのまま残さない。一般的な山括弧の文章を一括で削除せず、公式に定義された構文だけを認識して処理する。元の文章の校正・翻訳は行わない。

### 常に削除して無視するもの

次は設定の有無にかかわらず、SRT 本文から削除して無視する。

- 色、サイズ、フォント、文字装飾、プリセット、座標、字間・行間、文字変形などの装飾・レイアウト制御文字。
- コメント。
- Lua スクリプト制御文字。Exporter はスクリプトを実行せず、実行結果の文字列も再現しない。実行結果が AviUtl2 の表示文字数へ与える影響も扱わず、時間計算上は 0 文字とする。

設定画面には「装飾用の制御文字、コメント、Lua スクリプトは SRT 出力時に削除されます」と案内する。これらを含む Object ごとの警告は表示しない。

### ルビと絵文字

`字幕の整形` には次の独立したチェックボックスを置く。両方とも初期値はオンとする。設定は Windows のユーザー別設定へ保存し、次回 Exporter 起動時に復元する。

| チェックボックス | オン | オフ |
| --- | --- | --- |
| `ルビをカッコ書きで残す` | `</>漢字<!>かんじ</>` を `漢字（かんじ）` に変換する。 | ルビだけを削除し、親文字 `漢字` を残す。 |
| `絵文字をカッコ書きで残す` | `<&拍手>` を `（拍手）` に変換する。 | 絵文字を削除する。 |

### 時間制御

文字送り `<r>`、待機 `<w>`、表示クリア `<c>` は、`待機・クリアを反映` がオンのときに処理する。初期値はオンとする。制御文字を使わない本文では有効・無効で出力結果が変わらないためである。オンの場合は文字送りの**見た目を一文字ごとの SRT 字幕として再現しない**一方で、`<r>` を時間計算に使い、`<w>` と `<c>` による字幕境界を反映する。短い断片を大量に作る文字送り再現は、最小字幕時間による結合と相性が悪く、SRT の可読性も損ないやすいため対象外とする。オフの場合は3種とも削除して無視し、従来どおり Object 表示範囲全体を1つの候補にする。

#### 計算モデル

時間カーソルは Object 開始時刻から始める。標準テキストの初期表示速度を初期値とし、`<r数値>` は現在の速度を変更、空の `<r>` は初期値へ戻す。表示速度が 0 の場合は即時表示として、文字送りによるカーソル加算を行わない。

時間計算用の表示文字数は、SRT 本文へ変換した後の文字列の長さではなく、AviUtl2 上で表示される文字列から別途求める。したがって、`ルビをカッコ書きで残す` と `絵文字をカッコ書きで残す` のオン／オフは、待機・クリアの時刻を変えない。

| 入力要素 | 表示文字数 |
| --- | --- |
| 通常の半角英数・日本語 | 各 1 文字 |
| ルビ `</>親文字<!>読み</>` | 親文字と読みの各文字数の合計。SRT 用に追加するカッコは数えない。 |
| 絵文字 `<&名前>` | 登録済みかどうかを問わず 1 文字。名前の長さは数えない。 |
| 装飾・コメント・Lua スクリプト・時間制御文字 | 0 文字 |

結合文字、異体字セレクタなど、見た目と Unicode 上の文字数が一致しない文字列は、初期版の互換性確認対象外とする。

- 本文の各表示文字は現在のカーソル時刻で表示し、正の表示速度 `r` なら直後に `1 / r` 秒だけカーソルを進める。したがって、次の `<w>` または `<c>` は直前の文字の表示時間を含む時刻で処理する。
- `<w秒数>` はカーソルへ秒数を加える。`<w*秒数>` は待機時点で現在の字幕に表示されている文字数を掛けた秒数を加える。待機後の本文が、まだ本文を持たない字幕区間の最初の文字なら、その時刻を字幕開始とする。
- `<c秒数>` はカーソルへ秒数を加えた時刻で、現在の字幕を終了して本文と表示文字数をクリアする。`<c*秒数>` はクリア時点までの現在の字幕の表示文字数を掛けた秒数を加える。直後の改行は無視する。後続本文があれば、その最初の文字が同時点から新しい字幕を開始する。後続本文がなければ、Object 終端または次の表示文字まで字幕が存在しない区間となる。
- Object 終端は、表示中の字幕を終了する上限とする。制御文字で求めた時刻が終端を超える場合、終端以後の本文は候補にしない。

計算は内部で連続時間として行い、最終的な SRT 時刻だけをミリ秒へ丸める。AviUtl2 のフレーム単位表示との差が最大おおむね1フレームになることは許容する。

この前処理でできた字幕候補は、標準テキスト・セリフ準備・SRTrack Object の他の候補と同じ統合処理へ渡す。したがって、別の字幕開始による中断、同時開始時の並び順、フレーム範囲選択、最小字幕時間による結合は既存規則をそのまま適用する。

#### 実機検証済みの基礎挙動

30fps のテスト Object で、初期表示速度では `ABC` が開始フレームで全文表示されること、`<r10>` では各文字が3フレーム（0.1秒）ずつ表示されることを確認した。`<w1>` は直前の文字の表示時間後に1秒待機し、`<w*0.2>` と `<c*0.2>` は待機時点の表示文字数を倍率に使う。`<c>` は待機完了時に本文をクリアし、後続本文がなければ空表示となる。`<c>` 直後の改行は無視されることも確認した。半角英数・日本語・両者の混在は同じ 1 文字単位で数えられること、ルビの読みも文字数に含まれること、絵文字は登録の有無にかかわらず 1 文字として数えられることを確認した。

標準テキストでは `表示速度` 項目を初期表示速度として読む。セリフ準備で同項目を取得できない場合は、初期表示速度を0（即時表示）として処理する。`<r数値>` がある本文ではその時点から指定速度を用いる。
