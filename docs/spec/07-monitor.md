# 7. Monitor 廃止方針

## 7.1 廃止の理由

旧 Monitor は `UPDATE_OBJECT` 通知を常時受け、動画 Object の値や位置を SRTrack Object へコピーする初期実装だった。個々の処理は小さくても、動画編集では SRTrack と無関係な Object 更新が多数発生する。更新の大部分に常駐処理を介在させる構成は、実運用上の負荷と責務の両面で採用しない。

## 7.2 代替設計

SRTrack Object は Preview または Exporter が必要になった時点で、自身の1つ上のレイヤーにある動画 Object を直接参照する。動画の再生位置、速度、ループ、タイムライン範囲を Object へ複製しない。動画とのグループ化は編集操作を助けるが、監視・値同期・ファイル名同期の条件ではない。

このため、Monitor による値のコピー、手動変更の差し戻し、Object 名の自動更新、動画ファイル名からの SRT 自動差し替えは廃止する。`SRTrack.aux2` は Exporter と Importer を収録し、Monitor の論理コンポーネントおよび常駐イベントリスナーを持たない構成へ移行する。

## 7.3 移行上の注意

この文書は旧実装の廃止記録である。旧 Monitor の移動・分割・伸縮・リネームについての概略確認は、新しい直上参照方式の対応確認を意味しない。新方式は Preview と Exporter の実装後、標準動画との比較試験で別途検証する。
