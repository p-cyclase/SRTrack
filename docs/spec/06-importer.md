# 6. Importer

## 6.1 役割

Importer は、動画ファイルをタイムラインへ置く時点で、対応する SRT と SRTrack Object の関係を作るための GCMZDrops2 連携コンポーネントである。GCMZDrops2 の公開ハンドラースクリプト API が受け取るファイルドロップを対象とし、エクスプローラーと AviUtl2 内メディアエクスプローラーで簡易確認済みである。その他の追加経路は必要性が確認できた段階で追加検討する。

現行 Importer の責務は初期対応づけである。動画ファイルと同じフォルダに同名の SRT がある場合、動画オブジェクトと SRTrack Object を同時に作成し、Object の再生範囲終端を動画オブジェクトと同じフレーム境界の終端で初期化する。SRT を字幕として描画・出力する役割は持たない。

## 6.2 取込時の処理

1. 利用者が、導入済みの L-SMASH Works または標準 AVI 読込が動画トラックとして認識できるファイルをタイムラインへドロップする。
2. GCMZDrops2 が公開ハンドラー API でファイルリストを受け取り、Importer は動画と同じフォルダで、拡張子だけを `.srt` に置換した同名ファイルを探す。例：`movie.mp4` に対して `movie.srt`。
3. 対応 SRT が見つかった場合、Importer は動画ファイルを、動画と SRTrack Object を含む一時の複数オブジェクト `.object` へ置換する。標準動画オブジェクトのファイル参照はエイリアス内に保持する。
4. 動画オブジェクトと SRTrack Object を一組として配置する。AviUtl2 の複数オブジェクト・エイリアスの標準挙動により、二段が空く最初の後方時刻へ配置される。既存オブジェクトは移動しない。
5. 複数オブジェクト・エイリアスのグループ設定により、動画オブジェクトと SRTrack Object をグループ化する。
6. Object に SRT の参照先、再生開始位置 `P`、再生範囲終端 `E`、動画全長 `D`、再生速度、ループ再生を設定する。通常の初期値は `P = 0`、`E = D = 動画オブジェクトと同一のフレーム境界終端`、再生速度 `100`、ループ再生オフである。
7. 完成時は Object 名を対応する SRT ファイル名に設定する。SRT 未指定の手動配置 Object は標準名 `SRTrack` のままとする。

複数の対応ペアを一度にドロップした場合は、一つの複数オブジェクト・エイリアスにまとめる。ペアをファイル名順に同じ二層へ時間方向に並べ、各ペアだけに固有のグループ値を設定する。これにより、別動画のペアが同じグループにならない。

動画と同名の SRT が見つからない場合は、通常の動画読込を妨げない。Object を作らず、通知も表示しない。Importer は導入後に常時動作する想定のため、SRT に関係しない通常操作を通知で妨げない。利用者は必要に応じて手動で SRTrack Object を配置できる。動画と Object の二段分の空き区間を探す際、既存オブジェクトを移動してはならない。ドロップ先で置けない場合は、動画と Object のペア全体を後方の時刻へずらす。SRT が複数候補となる条件、後方に配置可能な位置がない場合の扱い、既存 Object との重複時の扱いは未決定とする。

## 6.3 再生範囲終端

`E` は、SRTrack Object が参照する **SRT 元時刻上の終端（秒）** である。タイムライン上の表示終了時刻、SRT 内の最終字幕の終了時刻、動画のファイル更新日時ではない。参照範囲は `[P, E)` とし、`E` は `P` より後でなければならない。

初回取込で `E` を動画オブジェクトと同じフレーム境界の終端から得ることにより、SRT に字幕が存在しない無字幕区間も含め、タイムライン上の正しい終端を表せる。SRT の最終字幕時刻から `E` を推定してはならない。

## 6.4 動画全長

`D` は Importer が取込時に設定する、動画オブジェクトと同じフレーム境界の長さ（秒）である。初回取込では `E` と同じ値になるが、役割は異なる。`E` は現在利用する範囲の終端であり、分割・伸縮に伴って変化する。`D` は元動画の基準長として、移動・分割・伸縮によって変化させない。

通常の字幕プレビューと Exporter の時間変換は `P`・`E`・速度を使う。ループ再生時だけ、`D` を元動画時間を繰り返す周期の基準として用いる。SRT の最終字幕時刻や、分割後の Object の長さで `D` を上書きしてはならない。

## 6.5 各要素の責務

| 要素 | 責務 |
| --- | --- |
| 現行 SRTrack Importer | 動画ドロップの受付、同名 SRT の検出、動画と Object の生成・グループ化、`P`・`E`・`D`・速度の初期設定 |
| Monitor（初期実装済み） | 取込後に動画 Object 本体が更新した `P`・`E`・再生速度・ループ・ファイル参照・タイムライン範囲を、管理対象 Object へ反映 |
| SRTrack Object | SRT 参照、`P`・`E`・`D`・速度の保持、編集用プレビュー |
| SRTrack Exporter | Object が保持する最終的な参照範囲を SRT から読み、シーン時刻へ変換して他字幕ソースと統合・出力 |
| SRTrack.mod2 | 編集画面専用の字幕表示と読込診断。動画出力には描画しない |

Importer は、取込後の分割・伸縮を常駐監視して `P`・`E` を更新する役割を持たない。継続同期は Monitor の責務である。Exporter・Importer・Monitor は完成時に一つの `SRTrack.aux2` に収録するが、ソースと仕様上の責務は混ぜない。Monitor の初期実装方針は [07-monitor.md](07-monitor.md) を参照する。

`P`、`E`、`D`、再生速度は、動画との同期を前提とする自動設定値である。AviUtl2 の UI 上で値を手動変更することは可能だが、その場合は動画との対応が崩れる可能性がある。手動変更は非推奨と明示するが、利用者の変更を拒否したり、値を自動で元に戻したりはしない。

手動変更の有無を検出・記録・判定する状態は持たない。Monitor を実装する場合は、動画側の `P`・`E`・再生速度が変化した結果を Object へ反映する。Object の手動値を維持するか、後続の動画側更新でそろえるかの詳細は、Monitor の仕様を実装前に決める。


## 6.6 実装・検証上の条件

GCMZDrops2 の公開ハンドラースクリプト API を使用する。ハンドラーは最終的に AviUtl2 へ渡すファイルリストを変更でき、公開 API のメディア情報取得からフレーム数を決める。固定の対応拡張子一覧は持たず、同名 SRT があるファイルについて動画トラックを取得できた場合だけ処理する。対応 SRT がある動画は、そのファイル参照を含む一時の複数オブジェクト `.object` に置換する。これにより、対応範囲は導入済みの L-SMASH Works または標準 AVI 読込が扱える形式に従う。GCMZDrops2、L-SMASH Works その他の外部プラグインや外部ファイルのリバースエンジニアリングは行わない。

SRTrack 自身の受け入れ条件は、動画と Object を同じ開始時刻・同じ長さで、Object を動画直下へ置き、二段とも空く最初の後方時刻までペア全体をずらすことである。外部字幕ツールの実装・スクリプト・設定内容を調査または再利用しない。

動画オブジェクトと同じ分割・伸縮時の結果を Object へ継続反映できるかは未検証である。初期実装は、GCMZDrops2 経由の動画情報取得、一時 `.object` の生成、単体・複数動画の二層配置、ペアごとのグループ化、`P`・`E`・`D`・速度の初期値保存を行い、AviUtl2 2.1.13 で簡易確認済みである。分割・伸縮後の `P`・`E` 更新と、その間も `D` が不変であることは、Monitor の標準動画との比較試験を通過するまで対応済みとしない。

### 未決定事項
