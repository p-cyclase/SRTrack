# 6. SRTrack Importer

## 6.1 役割

SRTrack Importer は、動画ファイルをタイムラインへ置く時点で、対応する SRT と SRTrack Object の関係を作るための GCMZDrops2 連携コンポーネントである。SRTrack Exporter、SRTrack Object、編集用 Preview モジュールに加わる第4の構成要素とする。初期実装は、GCMZDrops2 の公開ハンドラースクリプト API が受け取るファイルのドラッグ＆ドロップだけを対象にする。メディアエクスプローラーなど、この API を経由しない追加経路は必要性が確認できた段階で追加検討する。

Importer の責務は初期対応づけである。動画ファイルと同じフォルダに同名の SRT がある場合、動画オブジェクトと SRTrack Object を同時に作成し、Object の再生範囲終端を動画の総時間から初期化する。SRT を字幕として描画・出力する役割は持たない。

## 6.2 取込時の処理

1. 利用者が、L-SMASH Works の入力設定に登録済みで動画トラックを持つファイル、または `.avi` をタイムラインへドロップする。
2. GCMZDrops2 が公開ハンドラー API でファイルリストを受け取り、Importer は動画と同じフォルダで、拡張子だけを `.srt` に置換した同名ファイルを探す。例：`movie.mp4` に対して `movie.srt`。
3. 対応 SRT が見つかった場合、Importer は動画ファイルを、動画と SRTrack Object を含む一時の複数オブジェクト `.object` へ置換する。標準動画オブジェクトのファイル参照はエイリアス内に保持する。
4. 動画オブジェクトと SRTrack Object を一組として配置する。ドロップ先のレイヤー・時刻から後方の時刻へ探索し、動画を置ける区間と、その直下に Object を同じ区間で置ける区間がそろう最初の位置を選ぶ。
5. 複数オブジェクト・エイリアスのグループ設定により、動画オブジェクトと SRTrack Object をグループ化する。
6. Object に SRT の参照先、再生開始位置 `P`、再生範囲終端 `E`、動画全長 `D`、再生速度を設定する。通常の初期値は `P = 0`、`E = D = 動画の総時間`、再生速度 `100` である。

動画と同名の SRT が見つからない場合は、通常の動画読込を妨げない。Object を作らず、通知も表示しない。Importer は導入後に常時動作する想定のため、SRT に関係しない通常操作を通知で妨げない。利用者は必要に応じて手動で SRTrack Object を配置できる。動画と Object の二段分の空き区間を探す際、既存オブジェクトを移動してはならない。ドロップ先で置けない場合は、動画と Object のペア全体を後方の時刻へずらす。SRT が複数候補となる条件、後方に配置可能な位置がない場合の扱い、既存 Object との重複時の扱いは未決定とする。

## 6.3 再生範囲終端

`E` は、SRTrack Object が参照する **SRT 元時刻上の終端（秒）** である。タイムライン上の表示終了時刻、SRT 内の最終字幕の終了時刻、動画のファイル更新日時ではない。参照範囲は `[P, E)` とし、`E` は `P` より後でなければならない。

初回取込で `E` を動画の総時間から得ることにより、SRT に字幕が存在しない無字幕区間も含め、元動画の正しい終端を表せる。SRT の最終字幕時刻から `E` を推定してはならない。

## 6.4 動画全長

`D` は Importer が取込時に取得する元動画全体の長さ（秒）である。初回取込では通常 `E` と同じ値になるが、役割は異なる。`E` は現在利用する範囲の終端であり、分割・伸縮に伴って変化する。`D` は元動画全体の長さとして、移動・分割・伸縮によって変化させない。

通常の字幕プレビューと Exporter の時間変換は `P`・`E`・速度を使う。`D` は将来のループ処理でだけ、元動画時間を繰り返す周期の基準として用いる。SRT の最終字幕時刻や、分割後の Object の長さで `D` を上書きしてはならない。

## 6.5 各要素の責務

| 要素 | 責務 |
| --- | --- |
| SRTrack Importer | 動画ドロップの受付、同名 SRT の検出、動画と Object の生成・グループ化、`P`・`E`・`D`・速度の初期設定 |
| SRTrack Object | SRT 参照、`P`・`E`・`D`・速度の保持、動画と同じ編集操作後の時間的状態の表現、編集用プレビュー |
| SRTrack Exporter | Object が保持する最終的な参照範囲を SRT から読み、シーン時刻へ変換して他字幕ソースと統合・出力 |
| SRTrackPreview | 編集画面専用の字幕表示と読込診断。動画出力には描画しない |

Importer は、取込後の分割・伸縮を常駐監視して `P`・`E` を更新する役割を持たない。グループ化で動画と Object に同じタイムライン操作を適用し、Object 側が標準動画と同じ規則で `P`・`E` を変化させることを目標とする。

`P`、`E`、`D`、再生速度は、動画との同期を前提とする自動設定値である。AviUtl2 の UI 上で値を手動変更することは可能だが、その場合は動画との対応が崩れる可能性がある。手動変更は非推奨と明示するが、利用者の変更を拒否したり、値を自動で元に戻したりはしない。

手動変更の有無を検出・記録・判定する状態は持たない。値が手動変更されたかに関係なく、移動・分割・伸縮ではその時点の `P`・`E`・再生速度を基準に、動画オブジェクトと同じアルゴリズムを適用する。


## 6.6 実装・検証上の条件

GCMZDrops2 の公開ハンドラースクリプト API を使用する。ハンドラーは最終的に AviUtl2 へ渡すファイルリストへ一時 `.object` を追加でき、公開 API のメディア情報取得から動画全長を得られる。初期実装は L-SMASH Works で一般的な動画コンテナと `.avi` を候補とし、動画トラックを持つことを API で確認してから処理する。L-SMASH Works 側で独自に追加した拡張子は、初期実装の候補一覧に含まれない場合がある。動画ファイル自体は残し、L-SMASH Works または標準 AVI 読込の担当を置き換えない。GCMZDrops2、L-SMASH Works その他の外部プラグインや外部ファイルのリバースエンジニアリングは行わない。

SRTrack 自身の受け入れ条件は、動画と Object を同じ開始時刻・同じ長さで、Object を動画直下へ置き、二段とも空く最初の後方時刻までペア全体をずらすことである。外部字幕ツールの実装・スクリプト・設定内容を調査または再利用しない。

動画オブジェクトと同じ分割・伸縮時の挙動をカスタム Object が実現できるかは未検証である。初期実装は、GCMZDrops2 経由での動画長取得、一時 `.object` の追加、`P`・`E`・`D`・速度の初期値保存を行う。動画直下への配置、二段とも空く最初の後方時刻への移動、およびグループ化は、GCMZDrops2 と AviUtl2 の複数ファイルドロップで達成できるか実機確認が必要である。分割・伸縮後の `P`・`E` 更新と、その間も `D` が不変であることは、標準動画との比較試験を通過するまで対応済みとしない。

### 未決定事項

- 動画と Object の二段分を置ける後方の空き区間が見つからない場合の扱い。
- 同名 SRT は存在するが、読込または解析に失敗した場合にも Object を作成するか。
- `動画全長 D` を Object の設定画面に常時表示するか、内部の自動設定値として扱うか。
