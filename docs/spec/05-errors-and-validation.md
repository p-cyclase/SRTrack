# 5. エラー、互換性、検証

## 5.1 エラー時の原則

- Preview は、SRT ファイル、上側の直前動画Object、再生設定などの読込失敗を編集画面に個別の診断として表示する。
- Exporter は、取得・解析できない項目をエラー・警告として集計し、取得できた字幕の出力を続行できる。出力後モーダルと共通診断ログで、対象 Object と理由ごとの詳細を確認できる。
- 対象字幕が 0 件なら空の SRT は作成しない。
- 読み取れない入力を黙って欠落させない。部分出力を許す場合も、対象と理由を警告する。
- 出力成功時は、保存先、取得件数、出力件数、除外件数、エラー件数、警告件数を表示する。
- SRTrack Object の編集用プレビューで SRT を読めない場合は、空表示にせず、編集画面に読込失敗を明示する。ファイル出力中はこの診断表示も描画しない。
- エラー、警告、保存のキャンセルで、元のプロジェクトやオブジェクトを変更しない。
- Importer の動画ペア化でプロジェクト情報・メディア情報・同名 SRT・一時エイリアス生成の取得に失敗した場合、元のドロップファイル一覧を変更せず通常の入力プラグインへ渡す。Importer 設定では、次回起動時から動画ペア取込と SRT 単体取込を個別に停止できる。

### 5.1.1 常設診断の方針

公開後の不具合報告を再現・切り分けしやすくするため、SRTrack には利用者が必要時に確認・共有できる常設診断を設ける。これは常駐監視や利用履歴の収集ではなく、処理時に得られた失敗段階と分岐結果を、通常の利用を妨げない形で整理して表示する仕組みである。

- 初期実装では、Exporter、SRT 単体 Importer、動画ペア取込ハンドラーの登録結果を、同じセッション内の**共通診断ログ**へ記録する。利用者は Importer 設定パネルからログを確認、コピー、消去できる。ログはメモリ内の一定件数だけ保持し、AviUtl2 終了時に破棄する。ファイルへの常時保存や外部送信は行わない。
- **Preview** は、現在編集中の Object に関係する読込・参照失敗を編集画面上で具体的に表示する。字幕本文の代わりに空表示を行わない。Preview の画面内診断を共通ログへ記録する拡張は、公開された安全な連携経路を追加できた後に扱う。
- **Exporter** は、取得できた字幕の出力を優先する。警告・エラーがあっても可能な範囲で出力を完了し、その後に出力結果と診断内容をモーダル表示する。モーダルには件数、対象 Object、レイヤー、フレーム範囲、失敗段階、継続・除外の結果、および「診断情報をコピー」を示す。同じ内容を共通診断ログへも記録する。個々の失敗ごとに確認ダイアログを連続表示しない。
- **Importer** は、通常入力への委譲を優先する。取込を妨げるモーダルやトーストは表示しない。初期実装ではSRT単体取込と動画ペア取込ハンドラーの登録結果を記録し、Lua動画ハンドラー実行時の受理・委譲・失敗段階は公開された安全な連携経路を追加できた後に扱う。
- 各ログ項目は、発生日時、機能、重要度（情報・警告・エラー）、安定したエラーコード、人間向け説明、処理結果、Object 種別、レイヤー番号、フレーム範囲を持つ。SRTrack 版と、取得可能な場合は AviUtl2 版もコピー内容へ含める。初期実装ではExporterの候補数・出力数・除外数、SRT単体Importerの作成結果、ハンドラー登録結果を記録する。Preview、Lua動画ハンドラー、結合・延長の詳細は将来の記録対象とする。
- エラーコードは機能・段階・原因を表す安定した識別子とし、人間が読める説明と対にする。例として `EXP-SRT-READ`、`PRE-VIDEO-MISSING`、`IMP-ALIAS-CREATE` のような体系を採用する。これにより、文言を改善しても Issue 報告で同じ事象を追跡できる。
- 既定のログとコピー内容には、利用者の絶対パス、SRT 本文、動画内容、動画名、利用者名、プロジェクト内の不要な Object 名を含めない。パスが原因と疑われる場合も、拡張子、存在確認、文字種、長さなどの伏せた属性を優先する。追加情報が必要な場合は、利用者が内容を確認したうえで別途提示する。
- 調査中だけ追加する一時診断は、通常処理を変えないものに限る。原因確認と修正の実機確認後は削除し、公開版に残す必要がある情報だけをこの常設診断の設計へ取り込む。

#### 重要度と利用者への通知

診断ログの重要度は、利用者が確認・対応すべき度合いに応じて次の三段階とする。ログに残すことと、モーダルで作業を中断することを同一視しない。

| 重要度 | 通知方法 | 例 |
| --- | --- | --- |
| エラー | Exporter では出力後モーダルと共通ログ。出力不能ならその場のエラー表示と共通ログ | SRT を読めない、保存に失敗した、必要な再生設定を取得できない |
| 警告 | Exporter の出力後モーダルと共通ログ | SRT の一部区間が不正、指定レイヤーが見つからない、字幕候補の一部を意図せず除外した |
| 情報 | 共通ログのみ。モーダルは表示しない | Object 範囲の終端、上側の直前動画Objectがない区間での字幕終了、対象外の拡張子、同名 SRT がないための通常入力への委譲 |

`SRTrack Object` の上側に参照可能な動画がなくなることは、Preview では編集者が配置を確認できるよう画面内診断を表示するが、Exporter では字幕終了の正常条件である。Exporter は `EXP-VIDEO-END` の情報ログを残すだけで、警告件数にもモーダルにも含めない。動画が存在するにもかかわらず再生設定を取得できない場合は、意図しない除外の可能性があるためエラーまたは警告として扱う。

#### 初期実装の範囲

初期実装では、`SRTrack.aux2` 内で動く Exporter、SRT 単体 Importer、動画ペア取込ハンドラーの登録結果を共通ログへ記録する。Exporter はエラー・警告を出力後モーダルと共通ログの両方に示し、Importer 設定パネルからログの閲覧・コピー・消去を行える。

Preview の Object スクリプトが使う `SRTrack.mod2` と、GCMZDrops2 上で動く Lua 動画ハンドラーは、`SRTrack.aux2` のセッション内ログへ安全に渡す公開経路を持たない。このため、初期実装で非公開連携・自動ファイル保存・外部送信は行わない。Preview の既存画面内診断と、動画ペア取込ごとの詳細ログは、公開された安全な連携経路を設計できた時点で追加する。

## 5.2 互換性と依存関係

- 当面の対象は AviUtl ExEdit2 2.1.13。
- SRTrack Exporter は AviUtl2 Plugin SDK の同梱ヘッダーを使用する。SDK の日付だけで互換性を判断しない。
- SRTrack Importer は GCMZDrops2 と L-SMASH Works を前提プラグインとする。いずれも同梱せず、GCMZDrops2 は公開ハンドラースクリプト API のみを利用する。対象拡張子は標準 AVI 読込と L-SMASH Works の登録拡張子に合わせ、実際に取り込むのは公開メディア情報 API で動画トラックを確認できたファイルだけとする。
- Importer の `drag_enter` は対象拡張子だけを参照し、ファイルを開かない。同名 SRT の存在確認、メディア情報取得、エイリアス生成は `drop` 中に限定する。
- 旧単一 SRTrack Object の設定取得、SRT 出力、`SRTrack.mod2` による日本語パス読込とループ、GCMZDrops2 経由の同名 SRT 検出・二層配置・ペアごとのグループ化・複数動画のファイル名順配置は AviUtl2 2.1.13 で概略確認済み。新しい SRTrack Object／SRTrack Object (Standalone) の基本 Preview 動作も同環境で概略確認済みである。Monitor は廃止済みであり、現行方式の一部ではない。

Object／Preview は初期版完成とする。分割・伸縮・上側レイヤーに複数動画がある場合・複雑なループなどで標準動画と完全に一致するかの確認は、今後のバグフィクス・互換性確認に含める。未検証であることは、要求済み機能が未実装であることを意味しない。

### 外部製作物の扱い

SRTrack は、公開されている AviUtl2 の公式ドキュメントと Plugin SDK に基づく独立した実装とする。AviUtl2 標準オブジェクト以外の外部ファイルおよび外部製作物について、リバースエンジニアリングを行わない。

## 5.3 旧構成の検証項目（履歴）

以下は旧単一 Object と Monitor を前提にした検証記録である。新しい二種類の Object の正規の受け入れ条件ではない。

現行の Preview／Exporter 手動回帰確認は、[09-manual-regression-test.md](09-manual-regression-test.md) のテスト用プロジェクト計画に従う。Importer のドロップ確認はそのプロジェクトに含めず、別の空シーン試験として扱う。

手動回帰プロジェクトは、各実装変更の後に開いて Preview と Exporter の基礎挙動をまとめて観察する共通の実験場である。固定の正解 SRT による機械比較は行わず、出力 SRT とテストマップを照合して、今回の実装で何が起きたかを確認する。素材・プロジェクト・字幕 fixture の版管理と、ローカル動画および生成物の扱いは 09 の管理方針に従う。

### SRT 解析

1. UTF-8 BOM の有無、CRLF／LF、末尾空行、複数行本文。
2. 不正 UTF-8、不正時刻、番号欠落・重複、逆転区間、時刻順でない区間、重複区間、空白区間。
3. ファイル変更・移動・欠落・アクセス拒否。

### 時間変換

1. 等速、倍速、半速、再生開始位置、オブジェクト範囲からはみ出す字幕、境界一致。
2. 30 fps と分数フレームレート、長時間、端数時刻、再出力時の丸め誤差。
3. オブジェクト全体の移動の結果を標準動画と比較する。端変更・分割・伸縮は、Monitor が管理対象の標準動画の更新結果を Object へ継続反映できることを確認する。
4. GCMZDrops2 経由の動画ドロップ時に同名 SRT を参照する SRTrack Object が生成され、動画とグループ化されることを確認する。
5. 動画と SRTrack Object を組にして、移動、再生開始位置、速度変更、ループ、ファイル参照、アイテム長の結果が同期することを確認する。分割・伸縮の同期試験も行う。
6. SRTrack Importer が GCMZDrops2 経由で動画を受け取った場合、同じフォルダの同名 SRT を検出し、動画と Object を標準の複数オブジェクト・エイリアスから生成・グループ化して、動画全長 `D` を初期化できることを確認する。動画と Object の二段分を置ける最初の後方時刻への配置と既存オブジェクトが移動しないことも確認する。
7. Importer が動画全長 `D` を保存し、移動・分割・伸縮の前後で `D` が変化しないことを確認する。ループ再生時は `D` を周期として利用し、プレビューと Exporter が同じ字幕反復結果になることを検証する。
8. `P`、再生速度、`D` を手動変更した場合に、動画との対応が崩れる可能性を Object の UI または利用案内で確認できることを確認する。変更そのものは拒否・自動差し戻ししない。
9. Importer がエクスプローラーおよび AviUtl2 内メディアエクスプローラーからのファイルドロップで同じ結果を作ることを確認する。その他の追加経路は対象外とする。
10. 同名 SRT がない動画をドロップした場合、動画だけが通常どおり配置され、通知が表示されないことを確認する。
11. Monitor が動画側の `P`・再生速度・ループ・ファイル参照・タイムライン範囲の更新結果を Object に反映すること、`D` が不変であること、手動値の差し戻しと曖昧な組のスキップが仕様どおりであることを確認する。
12. Object の `再生位置` と再生速度が秒・百分率単位で確認・編集できることを確認する。
13. 出力範囲機能を実装した後は、通常の保存ダイアログを表示し動画出力を操作・待機しないこと、選択範囲の境界をまたぐ字幕の切り詰め、範囲開始をゼロ秒にした再基準化、番号の振り直しを確認する。
14. 保存済み `.aup2` の現在のシーン節にある `output.file` から、同じフォルダ・同じベース名の `.srt` が保存ダイアログの初期候補になることを確認する。複数シーンでは現在の `scene_id` の節だけを使う。
15. 未保存プロジェクト、`output.file` 未設定、読取不能な `.aup2`、未保存の書き出し先変更ではエクスポートが失敗せず、通常の保存ダイアログへ安全にフォールバックすることを確認する。候補値の取得がプロジェクトを変更しないことも確認する。

### 編集用字幕プレビュー

1. `字幕プレビュー` のオン・オフで、編集画面の SRT 字幕表示だけが切り替わることを確認する。
2. 再生開始位置と正の固定速度を変更し、`P + v × obj.time` に対応する SRT 字幕が表示されることを確認する。
3. ファイル出力時にプレビュー文字が動画へ描画されないことを確認する。
4. 外部で SRT を更新後、「キャッシュを破棄」で表示も更新されることを確認する。
5. Lua 側で SRT を読めない場合、編集画面には読込失敗が表示され、ファイル出力には診断文字を含めないことを確認する。
6. SRT 本文と読込失敗表示の両方について、標準の描画設定・オブジェクト順序にかかわらず編集画面で描画されることを確認する。
7. 日本語を含むフォルダ名・ファイル名の UTF-8 SRT を指定し、完成時の `SRTrack.mod2` 経由で字幕を表示できることを確認する。

### 出力統合

1. SRT、標準テキスト、対応する外部字幕準備オブジェクトを単独・混在で出力する。`SRTrack Object` と `SRTrack Object (Standalone)` の両方を同じ対象設定で扱うことを確認する。
2. 開始時刻順の候補処理で、別の字幕の開始、Object の終了、上側の直前動画Objectの消失が現字幕を終了することを確認する。中断された SRT 字幕は再開せず、次の SRT 字幕は本来の開始時刻で始まることを確認する。
3. 同時フレームに Layer 1 側から `a`、`b`、`c`、`d` を置き、0 秒の `a`・`b`・`c` を削除せず保持した後、短字幕結合で 1 秒の `abcd` になることを確認する。
4. 0.500 秒以上で指定する最小表示時間未満の通常の字幕が後続字幕へ区切りなしで結合され、末尾に結合先がない短字幕だけが同じ最小表示時間まで延長されることを確認する。延長結果が動画・シーン・選択範囲の終端を超えても出力されることを確認する。
5. シーン全体と AviUtl2 のフレーム範囲選択を比較し、範囲端をまたぐ字幕の切り詰め、範囲選択開始をゼロとする再基準化、番号の振り直しを確認する。
6. レイヤー選択、重複、空白、オフセット、異常な SRT 内重複、0 秒以下の最終区間を確認する。
7. 既存の SRTrack Exporter の出力結果と設定が損なわれないことを確認する。

## 5.4 旧構成の検証状態（履歴）

標準テキストからの字幕取得と SRT 出力、旧 SRTrack Object の配置・SRT 出力・編集用プレビュー・日本語パス読込・再生位置と正の固定再生速度への追従は AviUtl2 2.1.13 で開発者が概略確認済みである。統合後の `SRTrack.aux2` による旧 Object 由来字幕の出力と、`D` 周期の字幕プレビューも確認済みである。厳密な網羅試験ではない。

## 5.5 次期 Object モデルの受け入れ条件

1. SRTrack Object が上側の直前動画Objectの `P`・速度・ループを読んで字幕を変換し、動画の移動、分割、伸縮、速度変更に対する結果を標準動画と比較する。
2. SRTrack Object の範囲内で上側の直前動画Objectが切り替わる場合、重複区間ごとに別の動画値が使われることを確認する。
3. SRTrack Object の上側に動画がない時刻は Preview がエラーを表示し、Exporter が該当区間を字幕なしとして警告・失敗なく出力を継続することを確認する。
4. SRTrack Object の `D` が Importer で初期化され、移動・分割・伸縮で変化せず、ループ時の周期として使われることを確認する。
5. 動画ファイル名を変更しても SRTrack Object の SRT ファイル指定が自動変更されないこと、別名の動画と SRT を手動指定して使えることを確認する。
6. SRTrack Object (Standalone) が動画なしで `P`・速度・自身のタイムライン範囲から字幕を変換し、SRT 最終字幕以降を空表示・非出力にすることを確認する。
7. Preview が必要時だけ動画を参照し、SRTrack と無関係な Object 更新で常駐監視処理を行わないことを確認する。
8. Importer が動画全長を取得できない場合に `D=0` とし、非ループでは出力でき、ループ時だけ Preview が診断を表示することを確認する。
9. SRTrack 共通設定で同名 SRT 自動取込をオフにすると、同名 SRT があっても動画が通常読込へ渡ることを確認する。設定をオンへ戻した後、AviUtl2 を再起動してから取込が再開することも確認する。
10. SRT 単体をそれぞれ SRTrack Object、Standalone、処理しないとしてドロップし、指定した Object と最大字幕終了時刻の長さ、または通常読込への委譲が得られることを確認する。空・不正な SRT は SRTrack Object を使う設定では最小 1 フレームになることを確認する。
11. メディア情報取得、一時ファイル作成・書込み、Lua 例外を失敗させた場合に、動画・SRT の元ファイルが通常読込へ渡り、一部だけ消えないことを確認する。
