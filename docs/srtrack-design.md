## 1. 目的と構成

SRTrack は、AviUtl2 での SRT 字幕出力を支援するツールキットである。既存の字幕出力プラグインと、新たに設計する SRT 読み込みカスタムオブジェクトから構成する。

- 字幕出力プラグイン：タイムラインから字幕を集め、SRT に出力する。既存の対象は標準テキストと対応する外部字幕準備オブジェクト。
- SRTrack Object：SRT と再生に関する設定を保持し、動画の編集に合わせた字幕出力を支援する。

既存プラグインの詳細は [Exporter 出力仕様](components/exporter-specification.md) を参照する。本書の新機能に関する記述は提案であり、両者が矛盾する場合、既存の挙動については実装と既存仕様書を確認する。

### 対象と優先順位

この時点では UTF-8 の SRT 読み込み、時間変換、既存エクスポート機能との連携を必須要件としていた。後の方針で、動画と同名の SRT を初期対応づけする SRTrack Importer も中核構成に位置づけた。対象環境は既存プラグインに合わせ AviUtl ExEdit2 2.1.13 を当面の検証基準とし、他バージョンは互換性を確認して決める。

## 2. 想定する利用の流れ

1. 動画と、それに対応する SRT を用意する。
2. タイムラインに SRTrack Object を配置し、ファイルを指定する。
3. 動画の使用範囲や再生速度に対応させて、字幕側の再生設定を調整する。
4. 必要に応じ、標準テキストや対応する外部字幕準備オブジェクトと併用する。
5. 字幕出力プラグインから対象を選択し、編集後の時刻に対応した SRT を出力する。

動画と字幕をどう対応づけ、編集後の設定をどこまで自動で同期するかは未決定である（第 5 節）。

## 4. SRT の読み込み・解析

### 4.1 基本方針

UTF-8 で読み込み、各ブロックの番号、時刻行、本文を解析する。時刻は `HH:MM:SS,mmm` を基準とし、内部では整数ミリ秒として保持する案とする。本文は複数行を保持する。BOM の有無、CRLF・LF、末尾空行を含むファイルを検証対象とする。

時刻は数値と区切りを検証し、分・秒・ミリ秒の許容範囲、時間の桁数、前後空白の扱いを決める。解析後は字幕を少なくとも「開始、終了、本文、元ファイル内の順序」として表現する。内部の区間は開始を含み終了を含まない `[開始, 終了)` を候補とする。

### 4.2 未決定事項

- 不正な UTF-8、時刻行や番号の欠落、不正な区間を検出した場合に、全体を中止するか、該当ブロックを除外して警告するか。
- 番号の重複・欠落、時刻順でないブロック、字幕の重複、開始と終了が同じまたは逆転した区間の扱い。
- 本文中の空行、前後の空白、HTML 風タグなどの保持・除去方針。空行がブロック区切りと衝突する場合の解釈。
- 長時間の時刻、大きいファイル、字幕件数や本文サイズの上限と、超過時の挙動。

曖昧な入力を黙って変更せず、対象範囲と警告を明文化する。

## 5. 再生時間と同期

### 5.1 時間系

次の時間を区別する。

- **シーン時刻**：出力先タイムラインの基準時刻。
- **オブジェクト内時刻**：SRTrack Object の開始からの経過時間。
- **SRT 元時刻**：読み込んだファイルに記載された時刻。

固定の正の速度で、ループしない単純な場合の変換モデルは次のとおり。シーン時刻を `T`、オブジェクト開始時刻を `A`、元 SRT の再生開始位置を `P`、速度を `v` とすると、オブジェクト内時刻 `t = T - A` に対応する SRT 元時刻は `s = P + v × t` となる。`v = 1` は等速、`v = 2` は 2 倍速、`v = 0.5` は半速である。

エクスポート時は各字幕の元区間を、オブジェクトが実際に参照する SRT の再生範囲と交差させる。交差した区間の各端点 `s` を `T = A + (s - P) / v` で出力先へ変換し、オブジェクト範囲で切り詰める。交差が空の字幕は出力しない。これは固定の正の速度に限る設計案であり、逆再生・停止・ループ・可変速度の仕様ではない。

### 5.2 フレームと丸め

プロジェクトのフレームレートを有理数 `rate / scale` として扱う。フレーム `n` の時刻は `n × scale / rate` 秒であり、SRT の `m` ミリ秒に対応する理論上のフレーム位置は `m × rate / (1000 × scale)` である。小数フレームを許容する計算と実際のフレーム境界への丸めは区別し、途中の繰り返し丸めを避ける。

未決定：開始・終了をフレーム化する必要がある箇所、各端点の丸め方向、速度を含む計算の精度、最終 SRT のミリ秒への丸め。29.97 fps 系などの分数フレームレートと、入力・再出力時の許容誤差を検証する。既存プラグインはフレームからミリ秒への変換を行うため、統合時の丸めの順序も確認する。

### 5.3 動画への追従方法

以下は初期の選択肢であり、現行方針では SRTrack Importer による初期対応づけと、SRTrack Object 側の時間状態保持を組み合わせる方向を採用している。

1. **手動同期**：動画と字幕オブジェクトの位置・範囲・速度を利用者が合わせる。
2. **編集操作の連動**：グループ化などで移動・分割を一緒に行い、その他の設定を合わせる。
3. **動画設定の参照**：対象動画を指定し、必要な設定を取得して字幕へ反映する。

どの方式でも、動画と字幕の対応の指定、複数動画、移動・トリミング・分割後の状態、再生位置・速度の変更後の反映を定義する。方式 2・3 で必要な機能が利用できるかは AviUtl2 と SDK で検証が必要。

### 5.4 標準動画との一致範囲

目標は標準動画オブジェクトに沿う動作だが、全機能との同一性は未検証。まず固定の正の速度・ループなしを基準ケースとし、分割や端の変更で再生位置がどう変わるかを標準動画と比較する。速度 0、逆再生、ループ、再生位置・速度の移動方法、中間点、時間制御、シーンを介した利用の対応可否は別途決める。時間とともに速度が変わる場合、上記の固定速度の式は使えない。

## 6. エクスポートとの連携

### 6.1 現状と必要な拡張

既存プラグインは標準テキストと「セリフ準備」を対象とし、対象オブジェクトのレイヤー、範囲、テキストを取得する。SRTrack Object は現時点の対象ではなく、対応にはプラグイン側の変更が必要。

候補として、エクスポート時にオブジェクトを識別し、SRT ファイルパスと再生設定を取得して、プラグイン側でファイルを読み、字幕区間をシーン時刻へ変換する方式がある。識別方法、項目値や移動設定の取得、相対パスの基準、読み込み権限は実証前である。Lua とプラグインの二重実装で解析や時間変換が食い違わない構成も検討する。

標準テキスト、セリフ準備、SRT 由来の字幕は、共通の「開始、終了、本文、出所、レイヤー、安定した順序」などへ正規化して後段に渡す案とする。実際に必要な項目や内部構造は決定していない。

### 6.2 出力ルールの衝突

既存仕様では、字幕を開始順に並べ、最後以外は次の字幕の開始時刻で切り替える。空白を埋め、重複時にも前の字幕に戻らない。また、短い字幕の結合やオフセットがある。SRT を取り込む場合、この処理は元ファイルの意図的な無字幕区間や重複を変更し得る。

要決定：

- 元 SRT の区間・空白・重複を保持するか、既存の切り替えルールに統一するか。
- 混在する字幕に同じルールを適用するか、ソースごとに扱いを変えるか。
- 短い字幕の結合・最短表示時間・オフセットの適用範囲と順序。
- 同時刻の字幕、複数レイヤー、複数 SRT の重複を保持・結合・選択する方法と並び順。
- 既存の対象選択・レイヤー指定との関係、空本文・書式・制御文字の扱い。

出力ファイルの番号は出力順に付け直す案とする。SRT の出力区間が 0 秒以下になる場合の扱いも、既存のオフセット仕様との整合を確認する。

## 7. ファイル管理とエラー

- SRT の保存場所を絶対パス、プロジェクト基準の相対パス、または両方で扱うか決める。プロジェクトの移動・別 PC・ファイル名変更時の再指定手順が必要。
- 元 SRT の内容を取り込み時に固定するか、再生・エクスポート時に外部ファイルから読み直すか決める。外部編集後の更新検出、手動再読込、プロジェクト再開時の再現性に影響する。
- ファイル欠落、アクセス不可、不正データ、設定取得失敗を検出した際の通知方法を決める。エクスポートでは、部分出力を許す条件と、欠落があることの明示が必要。
- 読み込みや解析を繰り返す場合のキャッシュと無効化、長時間・大量字幕時の応答性を検討する。プレビュー追加時は特に重要。

## 8. 低優先度の機能

### 字幕プレビュー

初期版の必須要件には含めない。将来、現在時刻の字幕を画面に描画する場合は、表示と出力で同じ時刻変換・字幕選択を用いることを目標とする。フォント、位置、複数字幕、表示と出力の差は別途仕様化する。

### 動画と同名の SRT の自動検出（方針変更済み）

手動指定を基本とした補助機能としていたが、現行方針では SRTrack Importer の中核処理とする。動画と同じフォルダの同名 SRT を対象とし、検出できない場合も手動指定できることを前提とする。複数候補や既存指定の上書きは未決定である。

## 9. 検証計画・受け入れ条件の候補

仕様確定後に期待値を定め、少なくとも以下を検証する。

1. BOM の有無、改行、複数行字幕、不正 UTF-8・不正時刻、重複や空白を含む SRT を読み取る。
2. 等速・倍速・スロー、再生開始位置、範囲の前後ではみ出す字幕、境界に一致する字幕を変換する。
3. 整数・分数フレームレート、長時間、端数のある時刻、再出力による丸め誤差を確認する。
4. 動画と字幕を移動、端の変更、分割した際の結果を標準動画と比較する。対応外の操作は明示する。
5. SRT、標準テキスト、セリフ準備を単独・混在で出力し、レイヤー選択、重複、空白、結合、オフセットを確認する。
6. 元ファイルの変更・移動・欠落、不正データ、保存後の再読込、部分失敗を確認する。
7. 既存プラグインの従来の出力結果と設定が損なわれないことを確認する。

## 10. 先に決める事項と調査順

1. 動画と字幕をどの単位で対応づけ、編集をどこまで自動追従するか。
2. 初期版で対応する操作（分割、端の変更、固定速度など）と、標準動画との一致範囲。
3. 元 SRT の空白・重複を保持するか、既存の切り替え・結合ルールを適用するか。
4. エクスポート側からカスタムオブジェクトの識別と必要な設定の取得が可能かを実機・SDK で検証する。
5. 時刻と丸め、ファイル参照、エラー時の動作を具体化し、検証用の入力と期待結果を定める。
